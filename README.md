# CSQTT для Keenetic / Entware

Клиент оригинального **CSQTT 2.1.9** с локальной веб-панелью и WireGuard-мостом.
Штатный WireGuard-клиент Keenetic подключается к мосту на этом же роутере;
устройства для VPN выбираются в штатной политике доступа Keenetic.

**Проект находится в разработке. Установочный preview пока не опубликован.**
Состояние сборок, проверок и следующий шаг записаны в [STATUS](docs/STATUS.md).
Наличие исходников или готового файла не означает прохождение приёмки на роутере.

```text
Устройства → политика Keenetic → WireGuard Keenetic
                                     ↓ локальный UDP
                           Entware WG-мост → CSQTT → сервер
```

## Целевая система

- Keenetic Extra KN-1710, KeeneticOS 3.8.7, установленный Entware на USB.
- MIPS32r2 little-endian soft-float, glibc 2.27, класс памяти 128 МБ.
- Одна IPv4-политика VPN и 1–3 устройства; скорость определяется измерениями.
- Совместимый сервер оригинального CSQTT 2.1.9 и ссылка на звонок VK.

Перепрошивка не требуется. Обновление серверного протокола и совместимость
с другими форками CSQTT в этот перенос не входят.

## Как выглядит настройка

1. Установщик покажет LAN-адрес панели, по умолчанию с портом **8080**.
   Логин и пароль панели не требуются; слушатель привязан к домашнему LAN-адресу.
2. В панели укажите сервер `host:port`, пароль сервера и ссылку на звонок VK.
   Сохраните параметры и нажмите **Подключить**.
3. После получения адреса CSQTT скачайте **CSQTT.conf**. Профиль содержит
   локальный endpoint `127.0.0.1:51820`, MTU 1280 и адрес, выданный CSQTT.
4. Импортируйте файл в штатный WireGuard-клиент Keenetic. Назовите подключение
   **CSQTT**. Откройте дополнительные настройки и вручную задайте **MTU 1280**,
   оставив подстройку TCP MSS включённой. Затем включите использование для выхода
   в интернет. **KeeneticOS 3.8 игнорирует MTU из импортированного файла.**
5. Создайте политику **CSQTT**. В ней должно быть только это WireGuard-подключение,
   без основного провайдера и других резервных подключений. Назначьте устройства
   политике в интерфейсе Keenetic. Из **политики по умолчанию** подключение CSQTT
   исключите, оставив обычного провайдера. При необходимости отключите в ней
   автоматическое добавление новых подключений: иначе новый WG может попасть
   в маршрут устройств, которым VPN не назначен.
6. Проверьте соединение с одного назначенного устройства. Handshake WireGuard
   подтверждает локальный мост; DNS-проба панели — передачу UDP через CSQTT.
   Реальный TCP-доступ и отсутствие обхода VPN проверяются отдельно.

На физическом KN-1710 с KeeneticOS 3.8.7 проверены импорт loopback endpoint,
локальный handshake и двусторонние тестовые ICMP-пакеты размером 1280 байт.
Это проверка локального моста; реальный VPN остаётся отдельным этапом
[приёмки](docs/ACCEPTANCE.md).

### DNS и IPv6

Профиль использует DNS `9.9.9.9`. В Keenetic этот DNS должен быть привязан
именно к WireGuard-подключению CSQTT. Не добавляйте его одновременно к WAN
или как DNS для «любого подключения». Проверьте общие DNS/DoH/DoT и фильтры,
способные направлять запросы назначенных устройств вне политики.

Первая версия рассчитана на IPv4. При обнаружении активного IPv6 без защиты
от обхода запуск блокируется. Включение IPv6 не входит в установку клиента.

### Подтверждение VK

Когда VK потребует подтверждение, панель покажет кнопку создания ссылки для
Android Helper. HTTPS-брокер запускается внутри той же Go-службы только на
время подтверждения и привязывается к LAN, порт **8443**. Существующий Helper
исходного проекта использует проверку отпечатка сертификата и временную сессию.
Полная проверка настоящей CAPTCHA и Android Helper остаётся отдельным этапом
приёмки; сам APK не входит в Entware-пакет.

Для этой сессии используется существующий
[Android Helper preview.10](https://github.com/RATOR2000/csqtt-openwrt/releases/download/v0.1.0-preview.10/csqtt-helper-preview.10.apk)
из исходного проекта, не APK-пакеты OpenWrt. SHA-256 Android-файла:
`01d837fef92239db28951f7ce60f5a26eb77c1c33236e8bb188d4a84e7c4d8d4`.

## Установка кандидата разработчиком

До опубликованного preview используется явный локальный IPK и его контрольная
сумма. Соберите кандидат по [BUILD](docs/BUILD.md), перенесите пакет и
`scripts/install.sh` на USB роутера и сначала выполните проверку:

```sh
sh /absolute/path/install.sh --check /absolute/path/csqtt-entware.ipk SHA256
```

Замените пути и `SHA256` фактическими значениями из доверенной сборки.
Без `--check` та же команда устанавливает пакет. Третьим аргументом можно
указать домашний `LAN_IP:PORT`. Установщик проверяет архитектуру, прошивку,
компонент WireGuard, адрес домашнего интерфейса, память, USB и зависимости.
Контрольная сумма проверяет целостность файла; она не заменяет доверие к его источнику.

Панель из сети вышестоящего роутера проверяется через SSH-туннель на её LAN-адрес.
Открывать новые WAN-порты для неё не требуется.

Часто обновляемое состояние и сокеты службы находятся в RAM, в закрытом
`/tmp/csqtt`. Настройки и постоянные ключи сохраняются на USB в `/opt/etc/csqtt`.

## Управление, обновление и удаление

```sh
/opt/etc/init.d/S90csqtt status
/opt/etc/init.d/S90csqtt restart
/opt/etc/init.d/S90csqtt stop
```

Остановка CSQTT сохраняет штатную политику. При политике только с локальным
WireGuard устройства не получают прямого WAN-резерва. Доступ к локальной сети
и управлению роутером должен сохраняться.

Обновление выполняется установщиком с новым явным пакетом и SHA256. Закрытая
копия настроек сохраняется на USB перед обновлением. Настройки, идентификатор
CSQTT и ключи WireGuard не являются файлами пакета и сохраняются при обновлении
и удалении. Если сервер удалит запись устройства и выдаст другой адрес, панель
заблокирует передачу и предложит скачать профиль заново.

Перед окончательным удалением переведите устройства из VPN-политики в нужную
другую политику самостоятельно. Затем удалите `csqtt-entware` через Entware
opkg. Удаление пакета не меняет штатный WireGuard, политики и межсетевой экран.
