# Установка и настройка: шаг за шагом

[← Главная страница](../README.md) · [Скачать preview](https://github.com/RATOR2000/csqtt-entware/releases/tag/v0.1.0-preview.1)

Инструкция для **Keenetic Extra KN-1710, KeeneticOS 3.8.7 и уже установленного
Entware на USB**. Примеры используют домашний адрес Keenetic `192.168.2.1`.
Это пример LAN, а не адрес удалённого сервера VPN.

Если CSQTT уже настроен и нужен только повтор установки, переходите к
[обслуживанию](#maintenance). Повторно создавать подключения и политики не нужно.

## Что появится автоматически, а что нужно настроить

| Элемент | Для чего нужен | Кто создаёт |
| --- | --- | --- |
| Панель CSQTT на порту 8080 и служба Entware | Подключение к серверу, состояние, выдача WG-конфига | Установщик |
| Локальный WireGuard-мост | Принимает пакеты штатного WG и передаёт их CSQTT | Служба CSQTT |
| Подключение WireGuard **CSQTT** в Keenetic | Направляет трафик роутера в локальный мост | Вы импортируете файл из панели |
| Политика **ISP** | Обычный интернет через провайдера | Вы создаёте в Keenetic |
| Политика **CSQTT** | Интернет только через локальный WireGuard | Вы создаёте в Keenetic |
| Назначения устройств и привязка DNS | Определяют, кто пользуется VPN и через какой DNS | Вы настраиваете в Keenetic |
| **Keenetic Plus DSL / UsbDsl0** | Штатное подключение для USB DSL-модема, если оно есть в системе | Не создаётся установщиком CSQTT и для VPN не требуется |

**ISP — название политики, DSL — отдельное подключение. Это разные вещи.**
Назвать политику обычного интернета можно иначе; здесь используется имя ISP.
При подключении WAN Keenetic к LAN другого роутера выбирают существующее
Ethernet-подключение провайдера, например **Broadband connection**.

<a id="step-1"></a>
## Шаг 1. Подготовьте роутер и войдите в Entware

1. Подключите компьютер или телефон к **Wi-Fi/LAN самого Keenetic**.
   Устройство за вышестоящим домашним роутером не становится клиентом политики
   Keenetic только из-за доступности его веб-интерфейса.
2. Убедитесь, что обычный интернет через Keenetic уже работает.
3. Проверьте, что Entware установлен, USB подключён, а в Keenetic доступен
   компонент **WireGuard VPN**. Если раздел WireGuard отсутствует, проверьте
   компоненты в **Управление → Общие настройки**. Эта инструкция не требует
   обновления KeeneticOS и не устанавливает Entware на пустой USB.
4. Откройте терминал компьютера. Для Entware SSH на порту 222 выполните:

   ```sh
   ssh -p 222 root@192.168.2.1
   ```

5. Введите свой пароль Entware. Если SSH Entware у вас слушает другой порт,
   замените `222` своим. Пароль вводится по запросу SSH, не в команду.
6. Проверьте, что существует `/opt/bin/opkg`. Установочная команда выполняется
   в оболочке **Entware от root**. Штатная CLI Keenetic под admin — другой вход.

Установщик проверяет платформу, компонент WG, память, свободное место на USB
и домашний адрес панели. Если проверка не проходит, исправьте указанную причину;
не обходите её принудительной установкой IPK.

<a id="step-2"></a>
## Шаг 2. Установите CSQTT одной командой

Вставьте **всю строку целиком** в SSH Entware и нажмите Enter:

```sh
(set -eu; umask 077; tag='v0.1.0-preview.1'; /opt/bin/opkg update; /opt/bin/opkg install wget-ssl ca-bundle; stage=$(mktemp -d /tmp/csqtt-loader.XXXXXX); trap 'rm -rf "$stage"' 0; trap 'exit 1' HUP INT TERM; (ulimit -f 128; /opt/bin/wget --no-config --no-netrc --no-proxy --no-hsts --check-certificate --ca-certificate=/opt/etc/ssl/certs/ca-certificates.crt --max-redirect=0 --timeout=20 --tries=2 -qO "$stage/bootstrap.sh" "https://raw.githubusercontent.com/RATOR2000/csqtt-entware/refs/tags/$tag/scripts/bootstrap.sh") && sh "$stage/bootstrap.sh" "$tag")
```

Команда получает **v0.1.0-preview.1** из этого репозитория, проверяет HTTPS
и контрольные суммы. Дождитесь строки `CSQTT manager installed: http://...`.
Она подтверждает установку программы; сервер и политики настраиваются ниже.

По умолчанию панель открывается по адресу **http://192.168.2.1:8080/**.
Логин и пароль панели не требуются. Новые WAN-порты для неё открывать не нужно.

<details>
<summary>Если домашний адрес Keenetic отличается от 192.168.2.1</summary>

Адрес не определяется автоматически. При повторе используется сохранённый
адрес панели; при новой установке — `192.168.2.1:8080`.
Для другой подсети в конце команды замените:

```sh
sh "$stage/bootstrap.sh" "$tag"
```

на следующий вызов, подставив настоящий **домашний адрес Bridge0**:

```sh
sh "$stage/bootstrap.sh" "$tag" 'ДОМАШНИЙ_IP:8080'
```

Это замена части полной строки, а не отдельная команда после её завершения.
WAN-адрес, `0.0.0.0` и адрес вышестоящего роутера здесь не подходят.

</details>

<a id="step-3"></a>
## Шаг 3. Настройте подключение в панели CSQTT

1. В браузере устройства из LAN Keenetic откройте адрес из строки
   `CSQTT manager installed`. В нашем примере это **http://192.168.2.1:8080/**;
   при другом домашнем адресе используйте свой.
2. Заполните поля:

   | Поле | Что вводить |
   | --- | --- |
   | Сервер | `host:port` клиентского подключения CSQTT, например `server.example:46000`. Не URL веб-панели сервера |
   | Пароль сервера | Действующий пароль доступа CSQTT для этого устройства |
   | Ссылка на звонок VK | Полную ссылку, используемую вашим CSQTT |
   | DNS внутри VPN | Для этой инструкции оставьте `9.9.9.9` |

3. Нажмите **Сохранить**. Дождитесь сообщения о сохранении.
4. Нажмите **Подключить**.
5. Дождитесь **CSQTT: Подключён**, девяти транспортных соединений и полученного
   адреса профиля. Если требуется подтверждение VK, выполните
   [действия с Helper](#captcha).
6. Кнопка **Скачать CSQTT.conf** станет доступна после получения адреса.
   Сам файл понадобится на шаге 5; пока настройте обычную политику ISP.

На этом этапе **WireGuard: Ждёт Keenetic** — ожидаемое состояние: штатное WG
ещё не импортировано. Три показателя панели означают разное:

| Показатель | Что он подтверждает |
| --- | --- |
| CSQTT подключён | Авторизация и готовность транспортных каналов |
| WireGuard: Есть handshake | Локальное соединение Keenetic с мостом Entware |
| Проверка туннеля: Ответ получен | Ответ на автоматическую DNS-пробу через CSQTT |

Работу сайтов и правильность политики проверяют отдельно на шаге 8.

**Для изменения сохранённых параметров сначала нажмите Остановить.** При
включённом соединении поля и кнопка сохранения заблокированы. Пустые поля
ранее сохранённых пароля и ссылки VK означают «оставить прежнее значение».

<a id="step-4"></a>
## Шаг 4. Создайте ISP для обычного интернета

Этот шаг сохраняет обычный выход для устройств, которым VPN не нужен.
В KeeneticOS 3.8 встроенная **Политика по умолчанию** включает все подключения
и не редактируется. Поэтому для обычных клиентов используйте отдельную ISP.
Её лучше настроить **до** включения нового WireGuard для выхода в интернет.

1. Откройте штатную панель по домашнему адресу Keenetic:
   в примере **http://192.168.2.1/**, без порта 8080.
2. Перейдите в **Интернет → Приоритеты подключений**.
   На узком экране сначала раскройте меню. На странице выберите вкладку
   **Политики доступа в интернет**.
3. Нажмите **Добавить политику**, задайте имя **ISP**.
   Если такая политика уже настроена, откройте её вместо создания дубликата.
4. Оставьте флажок у реально используемого подключения провайдера:
   при Ethernet это обычно **Broadband connection**. Для PPPoE/L2TP выбирайте
   фактическое интернет-подключение вашей сети, а не имя из примера.
5. **CSQTT / WireGuard исключите** из ISP, если он уже есть в списке.
6. Выключите **Добавлять новые подключения автоматически**. Иначе импортируемое
   позже WG может попасть в обычную политику.
7. Если вы не пользуетесь DSL-модемом, флажок **Keenetic Plus DSL** в этой
   политике не нужен. Само штатное подключение удалять для CSQTT не требуется.
8. Примените изменения. Если интерфейс показывает кнопку сохранения, нажмите её.
9. Перейдите в **Мои сети и Wi-Fi → Домашняя сеть**. В блоке
   **Политика доступа для незарегистрированных устройств** выберите **ISP**.
   Повторите для используемой **Гостевой сети**.
10. В **Мои сети и Wi-Fi → Список устройств** проверьте карточки зарегистрированных
    обычных клиентов. В поле **Политика доступа** выберите **ISP** для тех,
    которым нужен выход через провайдера. Явные назначения других политик
    нужно учитывать отдельно от политики сегмента.

Ожидаемый состав ISP:

| Подключение | Включать в ISP? |
| --- | --- |
| Ваш действующий провайдер | Да |
| CSQTT / WireGuard | Нет |
| DSL, которым не пользуетесь | Не требуется |
| Автоматическое добавление новых подключений | Выключить |

<a id="step-5"></a>
## Шаг 5. Импортируйте WireGuard-профиль

1. Вернитесь в панель CSQTT на порту 8080.
2. Нажмите **Скачать CSQTT.conf** и сохраните файл на устройство, с которого
   открываете штатную панель Keenetic.
3. В Keenetic откройте **Интернет → Другие подключения**, раздел **WireGuard**.
   Выберите загрузку конфигурации из файла и укажите `CSQTT.conf`.
4. Назовите созданное подключение **CSQTT**.
5. Включите **Использовать для выхода в Интернет**.
6. В дополнительных настройках **вручную задайте MTU 1280** и оставьте
   **подстройку TCP MSS включённой**. KeeneticOS 3.8 игнорирует MTU при импорте.
7. Сохраните изменения и включите подключение.

Профиль уже содержит нужные ключи, выданный сервером IPv4, DNS,
`AllowedIPs = 0.0.0.0/0` и endpoint **`127.0.0.1:51820`**.
Это адрес моста **внутри этого же Keenetic**. Подменять его публичным адресом
VPN-сервера или адресом другого домашнего роутера не нужно.

Если панель сообщает об изменившемся адресе и необходимости обновить профиль,
скачайте свежий файл и обновите штатное WG-подключение. Установщик не заменяет
его автоматически. Сохраните MTU, привязку DNS и членство подключения в политике.

<a id="step-6"></a>
## Шаг 6. Проверьте DNS

1. В Keenetic откройте **Сетевые правила → Интернет-фильтр → Настройка DNS**.
   В узком окне вкладки могут быть спрятаны в выпадающем меню.
2. Найдите DNS **9.9.9.9**, добавленный профилем. Если его нет, добавьте его.
3. Убедитесь, что этот DNS привязан именно к подключению **CSQTT / WireGuard**.
   Не выбирайте вариант **для любого подключения** и не привязывайте тот же
   VPN DNS дополнительно к WAN.
4. Если в панели CSQTT выбран другой DNS, здесь должен быть тот же адрес
   с привязкой к WG-подключению.
5. Проверьте общие DNS/DoH/DoT и контентные фильтры: они не должны назначать
   VPN-клиентам прямой резервный DNS вне их политики. Обычные DNS провайдера
   для ISP могут оставаться привязанными к его подключению.

Установщик не меняет эти настройки Keenetic. Подробности обработки DNS описаны
в [справке Keenetic о политиках подключения](https://support.keenetic.com/runner-4g/kn-2212/en/17892-connection-policies.html).
Иллюстрации актуальной справки могут отличаться от интерфейса версии 3.8.

Первая версия CSQTT Entware рассчитана на **IPv4**. Не включайте IPv6 для
обхода ошибки запуска: при обнаружении активного IPv6 без защиты от обхода
активация блокируется. Настройка защищённой IPv6-сети в этот preview не входит.

<a id="step-7"></a>
## Шаг 7. Создайте политику CSQTT и выберите устройства

1. Откройте **Интернет → Приоритеты подключений**.
2. Нажмите **Добавить политику**, задайте имя **CSQTT**.
   При повторной установке используйте уже существующую политику.
3. Оставьте **единственный флажок у WireGuard-подключения CSQTT**.
4. Снимите флажки у Ethernet-провайдера, DSL, модемов и остальных подключений.
5. Выключите **Добавлять новые подключения автоматически**.
6. Примените изменения.
7. Подключите нужное устройство к Wi-Fi/LAN Keenetic.
8. В **Мои сети и Wi-Fi → Список устройств** откройте его карточку.
   Если устройство незарегистрированное, сначала зарегистрируйте его.
9. В поле **Политика доступа** выберите **CSQTT** и сохраните, если предлагается
   кнопка сохранения. Проверьте, что выбранное значение осталось CSQTT.

Итоговая схема:

| Кому нужен интернет | Назначение | Подключения в политике |
| --- | --- | --- |
| Выбранные VPN-устройства | CSQTT | Только WireGuard CSQTT |
| Обычные устройства | ISP | Действующий провайдер без WireGuard CSQTT |
| Новые незарегистрированные клиенты Home/Guest | ISP в настройках сегмента | Обычный провайдер |

**Добавление WAN вторым в CSQTT разрешит прямой обход при отказе VPN.** Чтобы
сохранить блокировку интернета при остановке CSQTT, в этой политике должен
оставаться только WG. Локальная сеть и панель роутера должны быть доступны.

Если телефон меняет случайный MAC для этой Wi-Fi-сети, проверьте, что Keenetic
по-прежнему распознаёт его как устройство с назначенной политикой CSQTT.

<a id="step-8"></a>
## Шаг 8. Проверьте результат один раз

1. На тестовом устройстве отключите мобильные данные и отдельный VPN;
   оставьте подключение к Wi-Fi/LAN Keenetic.
2. В панели CSQTT дождитесь девяти каналов, локального handshake WG и ответа
   автоматической DNS-пробы. После перезапуска штатному WG может понадобиться
   время на обновление локальной сессии; не создавайте повторные подключения.
3. Откройте несколько сайтов. Для проверки внешнего адреса можно один раз
   открыть **https://api.ipify.org/**: адрес должен соответствовать выходу VPN.
4. Для устройства в ISP проверьте обычный интернет. Сравнивайте устройства,
   подключённые именно к Keenetic: компьютер за другим роутером может уже
   использовать собственный VPN и показывать тот же адрес независимо от CSQTT.
5. Когда допустим краткий перерыв для VPN-устройств, нажмите **Остановить**
   в панели CSQTT. На назначенном устройстве новый внешний запрос в приватной
   вкладке должен перестать открываться, а адрес панели из шага 3 — остаться
   доступным. Уже загруженная страница или кеш не доказывают работу интернета.
6. Убедитесь, что устройство в ISP продолжает работать. Нажмите **Подключить**
   в CSQTT и проверьте восстановление интернета назначенного клиента.

Если при остановке свежие внешние запросы проходят, перепроверьте назначение
устройства, состав политики, мобильные данные, отдельный VPN и IPv6.
Один handshake WG не подтверждает выход через CSQTT или отсутствие обхода.

<a id="captcha"></a>
## Если VK запросил CAPTCHA

1. Используйте Android-телефон в Wi-Fi Keenetic. Откройте на нём панель CSQTT.
2. В блоке подтверждения скачайте **Android Helper preview.10**, если он ещё
   не установлен. В панели есть ссылка на существующий APK исходного проекта;
   [ссылка и SHA256 также указаны в README](../README.md#подтверждение-vk).
3. Нажмите **Создать ссылку для Helper**, затем **Открыть Android Helper**.
   Создавайте свежую ссылку для текущего задания; старую сохранённую не используйте.
4. Пройдите подтверждение на странице VK самостоятельно и вернитесь в панель.
   Дождитесь получения конфигурации сервера.

Helper использует временный локальный HTTPS-брокер на **LAN-порту 9443**;
открывать этот порт на WAN не требуется. Управляемое ядро не тратит попытки
на автоматические ответы. Если VK сообщает об исчерпанном лимите, остановите
повторы и дождитесь снятия ограничения со стороны VK.

**Ограничение preview:** реальное открытие VK и транспорт Helper проверены,
успешный возврат человеческого ответа ещё не подтверждён. Это остаётся
незавершённым этапом проверки, а не обещанием беспроблемной CAPTCHA.

<a id="maintenance"></a>
## Повторная установка, обновление и полный сброс

| Ситуация | Что делать | Что сохранится |
| --- | --- | --- |
| Повтор установки той же версии | Повторить команду шага 2 | Параметры CSQTT, UUID, WG-ключи, штатный WG и политики |
| Обновление | Использовать команду и точный тег из инструкции нового выпуска | Настройки сохраняет установщик; учитывайте примечания нового выпуска |
| Переустановка CSQTT при сохранённых `/opt/etc/csqtt` и конфигурации Keenetic | Шаг 2, затем проверить панель и интернет | Повторно создавать политики и WG не требуется |
| Сброс настроек Keenetic | Восстановить сеть/Entware при необходимости, затем пройти инструкцию | Штатный WG, DNS и политики нужно настроить заново |
| Форматирование или замена USB | Восстановить Entware и закрытую копию настроек, затем установить CSQTT | Без копии прежние UUID и WG-ключи не сохраняются |
| Сервер выдал новый адрес | Скачать свежий конфиг и обновить штатное WG | Политика остаётся; проверьте WG, MTU и привязку DNS |

Повтор установки проверен на физическом KN-1710 через публичную загрузку
GitHub. Он восстанавливает файлы программы той же версии и кратко перезапускает
CSQTT. Сохранённое включённое состояние возобновляет подключение.

В SSH Entware можно проверить или перезапустить службу:

```sh
/opt/etc/init.d/S90csqtt status
/opt/etc/init.d/S90csqtt restart
```

Настройки хранятся в `/opt/etc/csqtt`, закрытые копии установщика — в
`/opt/var/backups/csqtt`. Копия на том же USB не защищает от его форматирования;
сохраните её отдельно перед заменой носителя. Она содержит секреты: её и
файл `CSQTT.conf` не следует прикладывать к публичным issue.

<a id="troubleshooting"></a>
## Если что-то не работает

| Что видно | Что проверить |
| --- | --- |
| Команда `opkg` не найдена | Вы вошли в SSH Entware от root, а не в штатную CLI Keenetic |
| Установщик отклонил адрес панели | Он должен совпадать с домашним Bridge0; для другой подсети используйте вариант шага 2 |
| Панель с основного домашнего роутера не открывается | Она привязана к LAN Keenetic; подключитесь к нему либо используйте SSH-туннель ниже |
| «Сохранить» и поля неактивны | Сначала нажмите «Остановить»; при активном соединении это ожидаемо |
| «Подключить» неактивно после ввода | Сначала сохраните все обязательные параметры и дождитесь подтверждения сохранения |
| CSQTT не подтвердил конфигурацию | Проверьте клиентский порт, действующий доступ именно для этого устройства и совместимость сервера. Тайм-аут сам по себе не доказывает ошибку пароля |
| «Обновите WG-профиль» | Получен другой адрес CSQTT; повторно скачайте и импортируйте конфиг |
| «Ждёт Keenetic» после импорта | Проверьте, что штатное WG включено, endpoint остался `127.0.0.1:51820`, затем дайте локальной сессии восстановиться |
| Есть handshake, сайты не работают | Проверьте готовность CSQTT, DNS, MTU 1280, MSS и назначение устройства политике |
| Helper отклоняет ссылку | Обновите панель, создайте новую ссылку, используйте preview.10 и Wi-Fi Keenetic; актуальный порт брокера — 9443 |
| Телефон вышел через провайдера | Проверьте его регистрацию/MAC, выбранную политику и отсутствие WAN в CSQTT |

Для просмотра панели с компьютера за вышестоящим роутером откройте отдельный
терминал и выполните, заменив `KEENETIC_ADDRESS` доступным адресом **самого
Keenetic** и при необходимости порт SSH Entware:

```sh
ssh -N -L 127.0.0.1:18080:192.168.2.1:8080 -p 222 root@KEENETIC_ADDRESS
```

Если панель использует другой домашний адрес или порт, замените также
`192.168.2.1:8080` внутри команды её фактическим адресом из шага 3.

Оставьте терминал открытым и перейдите на **http://127.0.0.1:18080/**.
Здесь `127.0.0.1` — компьютер; в WG-профиле такой же адрес относится к самому
роутеру. Новые правила WAN-доступа к панели создавать не нужно.

Preview проверен с одним физическим клиентом и параллельными синтетическими
потоками. Три физических устройства и успешный возврат CAPTCHA ещё не
квалифицированы; скорость не гарантируется. История проверок — в [STATUS](STATUS.md).
