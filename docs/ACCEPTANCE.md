# Приёмка кандидата

Этот список описывает обязательные проверки. Выполненные этапы и привязка
к commit/артефакту фиксируются в [STATUS](STATUS.md); пункты ниже сами по себе
не являются доказательством выполнения.

## 1. Исходники и хост

- Закреплены исходники оригинального CSQTT 2.1.9, лицензия и авторство.
  Исходный OpenWrt-репозиторий остаётся без изменений.
- Проходят Rust-тесты, Go unit/race/vet и тесты IPK. Для моста проверяются
  реальный программный WG handshake, возврат пакетов, неверный source,
  переполнение ограниченных очередей, остановка и повторный запуск.
- API не возвращает пароли, ссылки VK и ключи в статусе или диагностике.
  Некорректные Host/Origin, CSRF, большой или лишний JSON отклоняются.
- WG-профиль скачивается явным запросом. Его приватный ключ не попадает
  в журнал или Git. Пустые поля редактирования не стирают сохранённые секреты.
- Настройки, идентичность CSQTT и WG-ключи сохраняются после обновления
  и удаления IPK; пакет не содержит файлов данных владельца.

## 2. MIPS и запуск

- ELF ядра соответствует MIPS32r2 LE O32 soft-float и glibc ≤2.27; загрузчик
  и runtime-библиотеки находятся в `/opt`.
- Проходят QEMU-проверки атомарных операций, контрольных векторов и запуска.
- На физическом KN-1710 запускаются обе программы. Панель доступна только
  на выбранном LAN-адресе; основное управление и WAN продолжают работать.
- Служба корректно распознаёт процесс через фактический путь USB, останавливает
  принадлежащие ей процессы и не затрагивает чужие службы.
- Installer `--check` на целевом роутере проверяет совместимость без установки.
  Реальная установка и удаление проверяются отдельно от host-тестов упаковки.
- Установка не выдаёт ошибок распаковки; после неё присутствуют все файлы
  из payload, включая вложенные лицензии. Успешного exit code opkg недостаточно,
  если в его выводе есть ошибки записи или файлы отсутствуют.

## 3. Локальный WireGuard и CSQTT

Сначала используется отдельный тестовый профиль без назначения обычных
устройств и без изменения основного подключения.

- Штатный импортёр Keenetic принимает профиль с endpoint `127.0.0.1:51820`.
  Если нет, проверяется собственный LAN endpoint с точным LAN-слушателем.
  Пока выбранный вариант не доказан, поддержку подключения объявлять нельзя.
- Штатный клиент выполняет handshake и двусторонний обмен пакетами с мостом.
  Расшифрованные пакеты не проходят через второй серверный интерфейс ядра.
- В дополнительных настройках штатного подключения вручную задан MTU 1280,
  подстройка TCP MSS включена. Импортёр KeeneticOS 3.8 игнорирует строку MTU;
  фактическое значение интерфейса проверяется отдельно после импорта.
- Для VPN-клиента CSQTT сохраняется идентификатор и полученный адрес.
  Keenetic преобразует source назначенных клиентов в адрес WG-профиля;
  посторонние source мост отклоняет.
- Реальная авторизация VK и получение каналов CSQTT завершаются успешно.
  DNS-проба через raw-IP endpoint получает проверенный ответ.
- Смена назначенного адреса блокирует мост до скачивания нового профиля.
  Старый статус от другого PID, поколения или загрузки не включает мост.
- Отдельно проверяется настоящая CAPTCHA: создание Helper-сессии, завершение,
  отмена, истечение и отклонение позднего ответа. Один успешный программный
  тест брокера не считается проверкой реального Android Helper.

## 4. Политика и отсутствие обхода

Пользователь предоставляет одно тестовое устройство в LAN и вводит серверные
параметры через панель. Все проверки затрагивают только эту тестовую политику.

- Политика **CSQTT** содержит только локальное WG-подключение, без WAN-резерва.
  Назначенное устройство использует CSQTT, неназначенное — обычного провайдера.
- В политике по умолчанию CSQTT исключён; автоматическое добавление подключений
  не возвращает его туда. Существующие WAN-подключения и назначения сохранены.
- Работают TCP, UDP, DNS по UDP/TCP, длительные соединения и пакеты около
  MTU 1280. Проверяется возврат фрагментов и ICMP-ошибок без переписывания пакетов.
- DNS-профиль привязан к WG. Нет общего DNS «для любого подключения» или
  фильтра, уводящего проверяемые запросы тестового устройства в WAN.
  Для захвата используется уникальный тестовый запрос, чтобы отличить его
  от служебного разрешения имён CSQTT/VK.
- Для тестового устройства не существует прямого IPv6-обхода. При обнаруженном
  активном IPv6 без защиты запуск первой версии блокируется.
- При обычной остановке CSQTT и моста тестовое устройство теряет интернет,
  сохраняя доступ к роутеру и локальной сети; остальные устройства продолжают
  работать через свои политики.
- Перезапуск службы, повторное подключение и смена адреса не дают краткого
  прямого WAN-доступа. Одна свежая WG-сессия не считается доказательством VPN.

## 5. Нагрузка и вмешивающиеся испытания

- При одновременной работе 1–3 устройств измеряются RSS процессов, доступная
  память, CPU, скорость, задержка панели и восстановление. Требуются отсутствие
  OOM, зависаний и устойчивого роста памяти, запас MemAvailable не менее 16 МиБ.
  Скорость указывается только по измерению конкретного кандидата.
- Проверяются пики авторизации, работы Helper и повторного подключения,
  а также ограничение перезапусков при длительной ошибке.
- Перезагрузка роутера, физическое извлечение USB, разрыв WAN и имитация
  отказа сервера выполняются **только после отдельного разрешения пользователя**.
  До их выполнения соответствующие проверки отмечаются как незавершённые.
- В разрешённом сценарии отсутствия USB штатная политика должна продолжать
  блокировать WAN-обход, сохраняя управление и работу остальных политик.

Публичный installable preview выпускается только после прохождения необходимых
этапов этого кандидата. Сборка, эмуляция, локальный WG и реальный VPN отражаются
в отчёте раздельно.
